# Transcribator for macOS

Нативная menu-bar утилита, которая записывает системный звук и микрофон, сохраняет M4A и отправляет его в OpenAI Transcriptions API или через текущий вход ChatGPT в режиме GPT App.

## Главное

- Никаких виртуальных аудиодрайверов, Docker, Python или ffmpeg.
- Один приватный Core Audio tap для всего системного звука.
- Системный tap и микрофон записываются независимыми каналами, затем сводятся в один M4A.
- Микрофон включается и выключается прямо во время записи; при mute в его дорожку записывается тишина, поэтому синхронизация с системным звуком сохраняется.
- Запись можно отменить отдельной кнопкой: обе дорожки останавливаются, временное аудио удаляется, API не вызывается.
- Для микрофона и системного звука отдельно задаются коэффициенты `0.00…1.00`; их можно менять во время записи, и каждое изменение применяется с соответствующего момента.
- Отдельный раздел принимает поддерживаемые macOS аудио- и видеофайлы, локально извлекает только аудиодорожку и приводит её к mono AAC M4A.
- AAC mono с выбором качества: 32, 64 или 128 kbps.
- Для API-моделей запись отправляется целиком, пока она не превышает 30 минут и 24 MB; для GPT App применяются короткие части (см. ниже).
- Более длинные или большие файлы делятся на минимальное количество равных частей: не длиннее 30 минут и около 20 MiB каждая.
- Модель выбирается прямо в menu bar: `gpt-transcribe`, `gpt-4o-transcribe-diarize`, `whisper-1` или четвёртый пункт **GPT App** (`gpt-app`).
- API key хранится в macOS Keychain.
- Настройки раскрываются внутри menu-bar окна и сворачиваются нижней кнопкой.
- API key и отдельные папки для аудио и транскриптов настраиваются там же.
- Сохранение итогового M4A можно отключить; тогда после транскрибации остаётся только TXT.
- Копирование готового текста в буфер обмена настраивается отдельно и по умолчанию выключено.
- По умолчанию микрофон сводится с коэффициентом `1.00`, системный звук — `0.65`.

## Значок и статусы

В строке меню всегда остаётся знак Transcribator размером 18×18 pt. Статус накладывается круглым бейджем на нижний правый угол логотипа, не увеличивая его ширину. Под белым символом расположен цветной фон: красный для записи и ошибки, оранжевый для выключенного источника или отсутствующего API key, синий для обработки, зелёный для готового результата, серый для отмены. Перечёркнутый микрофон или динамик обозначает отключённый источник, восклицательный знак — оба выключенных источника. При записи с выключенным источником маленькая красная точка в верхнем правом углу сохраняет индикацию записи. Обработка и результаты имеют приоритет над настройками источников. Основной знак адаптируется к светлой и тёмной теме. Подсказка и текст в окне поясняют состояние обоих источников.

Микрофон и системный звук занимают две компактные строки в основном окне. Переключатели всегда видны, а нажатие на процент раскрывает ползунок только для выбранного источника. Повторное включение восстанавливает последнюю ненулевую громкость. Нулевая громкость явно показана как `0%`; открытый ползунок можно вернуть с нуля тем же движением. Если оба источника выключены, новая запись недоступна; в уже начатой записи появляется предупреждение о тишине, а остановка остаётся доступной. Эти статусы описывают настройки источников в записи, а не измеренный сигнал или системную кнопку mute на Mac.

Во время обработки источники заблокированы, а предупреждение об их громкости скрыто: настройки записи не влияют на транскрибацию выбранного файла. Изменение и удаление API key недоступны во время записи и обработки. Длинные сообщения об ошибках не обрезаются; содержимое окна прокручивается, если не помещается на экране.

## Транскрибация файла

Нажмите `Транскрибировать файл…`, выберите аудио или видео, при необходимости добавьте имена и термины в поле контекста и запустите обработку. Используются выбранные в основном окне модель и качество. Для модели с разделением по говорящим контекст отключён, потому что этот API-параметр ею не поддерживается.

Исходный файл не изменяется. Для видео приложение читает только первую аудиодорожку; видеоданные не попадают ни во временный M4A, ни в API-запрос. Подготовленный M4A и upload-фрагменты удаляются после успеха, ошибки или отмены. В пользовательской папке остаётся только TXT. Сжатие уменьшает размер и время загрузки, но продолжительность записи по-прежнему определяет объём распознаваемой речи.

## Дистрибутивы и публикация

Актуальная версия — **0.2.1**, [дистрибутивы на GitHub](https://github.com/Knstxx/TRANScribator/releases/tag/v0.2.1). Локальная папка `dist/` содержит текущие `.app`, Universal `.dmg`, `.zip` и `SHA256SUMS`; сгенерированные бинарники не коммитятся в Git.

Публикация тега `v<версия>` запускает `.github/workflows/release.yml`: он сверяет версию с `Info.plist`, выполняет проверки, собирает Universal-приложение и публикует архивы с контрольными суммами в GitHub Releases. Описание берётся из `Releases/v<версия>.md`. Текущий канал — preview, сборки подписываются ad-hoc. Бинарники собираются непосредственно из помеченного коммита, без локальных сессий, ключей или записей.

## Сборка

Требуется macOS 15+ и Swift 6 из Xcode Command Line Tools.

```bash
cd macos
./Scripts/build-app.sh
open dist/Transcribator.app
```

`build-app.sh` собирает Universal-приложение с архитектурами `arm64` и `x86_64`, поэтому один bundle подходит для Apple Silicon и Intel Mac.

Исходник логотипа — `Resources/AppIcon.png`. При каждой сборке `Scripts/build-icon.sh` создаёт полный набор размеров 16–1024 px и собирает `AppIcon.icns` системными `sips` и `iconutil`. Иконка включается в подписанный bundle и используется в Finder и заголовке приложения. Промпт генерации сохранён в `Resources/Branding.md`.

Готовые ZIP и DMG для передачи на другой Mac создаются отдельно:

```bash
./Scripts/package-distribution.sh
```

Архивы и файл `SHA256SUMS` появятся в `dist/`. Без флага `--notarize` скрипт всегда создаёт ad-hoc сборку для разработки. На другом Mac сначала попробуйте открыть приложение один раз, затем разрешите его через `System Settings → Privacy & Security → Open Anyway`; отключать Gatekeeper целиком не следует.

Для публичной Developer ID-сборки сначала сохраните учётные данные нотариуса в Keychain:

```bash
xcrun notarytool store-credentials "TranscribatorNotary" \
  --apple-id "your-apple-id" \
  --team-id "YOUR_TEAM_ID"
```

Пароль приложения `notarytool` запросит интерактивно. Затем выполните:

```bash
export TRANSCRIBATOR_SIGNING_IDENTITY='Developer ID Application: Name (TEAMID)'
export TRANSCRIBATOR_NOTARY_PROFILE='TranscribatorNotary'
./Scripts/package-distribution.sh --notarize
```

Скрипт включает Hardened Runtime, подписывает приложение и DMG, нотарифицирует приложение и DMG, прикрепляет tickets, проверяет системную политику и только после этого считает SHA-256. Apple ID, пароль и сертификаты в репозитории не хранятся.

При первом запуске macOS запросит доступ к микрофону и записи системного аудио. После выдачи разрешения может потребоваться перезапуск приложения.

## Тесты

```bash
cd macos
swift run TranscribatorCoreChecks
./Scripts/check-gpt-app-session.sh
./Scripts/check-status-ui.sh
./Scripts/check-menu-ui.sh
```

В установленном Command Line Tools отсутствуют XCTest/Swift Testing, поэтому проверки собраны в отдельный исполняемый target и завершаются с ненулевым кодом при любой ошибке.

Проверки GPT App не используют настоящую сессию или сеть: тестируют фиксированный адрес загрузки, запрет редиректов, отсутствие API fallback и принудительного обновления сессии, безопасные ошибки, короткие части аудио и отмену. `check-gpt-app-session.sh` отдельно запускает подставной локальный helper и проверяет JSONL, обработку ошибок, фильтрацию окружения, таймаут и завершение дочернего процесса.

Проверки статусов покрывают сочетания источников, нулевую громкость, отсутствие API key и приоритет записи/обработки/результатов/ошибок. `check-status-ui.sh` отдельно рисует реальные SwiftUI-компоненты в светлой и тёмной темах и проверяет маленькие значки. Этот скрипт не создаёт `AppState`, не запускает приложение, не читает Keychain и не обращается к аудиозахвату; изображения сохраняются в `.build/status-preview/`.

`check-menu-ui.sh` проверяет целое меню с закрытыми и раскрытыми настройками в обеих темах, включая единственную область прокрутки. Он собирает реальные представления с отдельным состоянием предпросмотра без доступа к настройкам пользователя, Keychain, авторизации и записи. Установленное приложение не запускается и не изменяется; изображения сохраняются в `.build/menu-preview/`.

Полный smoke-тест разрешений и реального Core Audio capture можно запустить из собранного bundle:

```bash
./dist/Transcribator.app/Contents/MacOS/TranscribatorMac --capture-smoke
```

Он начинает с выключенным микрофоном, включает, снова выключает и включает его во время записи, а затем отдельно проверяет непрерывный участок тишины и возвращение сигнала после unmute. Системный звук и итоговый M4A также проверяются, временная папка удаляется.

Режим без микрофона проверяется отдельно и не запрашивает доступ к нему:

```bash
./dist/Transcribator.app/Contents/MacOS/TranscribatorMac --capture-smoke-system-only
```

Остановку и удаление незавершённой записи без API проверяет отдельный smoke-тест:

```bash
./dist/Transcribator.app/Contents/MacOS/TranscribatorMac --capture-cancel-smoke
```

По умолчанию результаты сохраняются в понятных пользовательских папках:

```text
~/Documents/Transcribator/Audio/
~/Documents/Transcribator/Transcripts/
```

Обе папки независимо меняются через `Настройки…` в menu bar. Аудиозапись и транскрипт получают одинаковое имя по времени начала записи, например `2026-08-04_15-45-02.m4a` и `2026-08-04_15-45-02.txt`.

Если выключить «Сохранять аудиозапись после транскрибации», настройка папки Audio блокируется, итоговый M4A не копируется, а рабочая запись удаляется после API-запроса.

Временные CAF, рабочий M4A и upload-фрагменты хранятся отдельно в Application Support и удаляются после обработки — в том числе после ошибки. Пустая рабочая папка также удаляется. При следующем запуске приложение очищает файлы, оставшиеся после аварийного завершения; старые тестовые и recovery-каталоги в системной временной папке удаляются через сутки. В пользовательских папках остаются только выбранные итоговые M4A и TXT.

## GPT App: текущая сессия ChatGPT

Четвёртый пункт **GPT App** использует диктовку ChatGPT через существующий вход на этом Mac. Отдельный Platform API key не нужен. Это название режима: сервер сам выбирает модель распознавания, поле `model` не передаётся.

В **Настройки → GPT App · ChatGPT** отображается состояние подключения. Используется только существующая сессия приложения. Отдельного входа, OAuth-интерфейса, формы токенов или кнопки авторизации в Transcribator нет. При отсутствии или истечении сессии GPT App нельзя выбрать: сначала войдите в само приложение ChatGPT, затем нажмите **Проверить подключение**. Так же обновляется подключение после установки или смены аккаунта.

Для режима требуется установленный совместимый ChatGPT/Codex с встроенным `codex app-server`. У проверенной версии ChatGPT bundle ID — `com.openai.codex`. Helper использует существующий общий профиль из `CODEX_HOME`, если он задан, иначе стандартный профиль Codex; подключение не обращается к IPC запущенного GUI-процесса. Старое приложение ChatGPT без этого компонента не предоставляет необходимый интерфейс: появится предложение обновить приложение. При отсутствии приложения GPT App остаётся видимым, но недоступным для выбора. Сохранённый недоступный режим блокирует обработку и показывает причину; автоматического перехода на платный API нет.

Транскрибация использует внутренний адрес `https://chatgpt.com/backend-api/transcribe`. Совместимость и лимиты этого недокументированного интерфейса могут измениться. GPT App делит длинные записи на минимальное количество равных частей не длиннее **9 минут 50 секунд**: по выбранной пользователем настройке остаётся 10 секунд до десятиминутной границы. Часовая запись делится на 7 частей. Дополнительно проверяется размер каждой части — не больше 24 MB (24 000 000 байт); этот локальный порог допускает 9:50 аудио во всех доступных качествах AAC. Части отправляются последовательно, текст объединяется. Разделение по говорящим и дополнительный контекст в этом режиме не поддерживаются. У трёх API-моделей прежняя политика до 30 минут / 24 MB сохраняется.

Безопасность подключения:

- Запускается только компонент установленного приложения с проверенной подписью OpenAI. Произвольный бинарник из PATH или переменных окружения не используется.
- Входом управляет само приложение ChatGPT; Transcribator не запускает новый вход или принудительное обновление токенов. Transcribator не читает `auth.json`, cookies браузера или секреты чужого Keychain.
- Временный access token получается через локальный RPC `getAuthStatus` и используется в памяти для запроса к фиксированному HTTPS-адресу ChatGPT. Этот RPC также внутренний и устаревший.
- Токен не сохраняется в настройки, файлы результатов, аргументы процессов или журналы Transcribator. HTTP-перенаправления запрещены, cookies и дисковый HTTP-кэш отключены. В ошибки не попадают заголовки и тела ответов авторизации.
- API key для первых трёх моделей остаётся в macOS Keychain и не участвует в запросах GPT App.

Проверка установленного приложения и существующей сессии без вывода токена и без загрузки аудио:

```bash
./dist/Transcribator.app/Contents/MacOS/TranscribatorMac --check-gpt-app
```

Для обработки файла через этот режим:

```bash
./dist/Transcribator.app/Contents/MacOS/TranscribatorMac \
  --transcribe-existing /path/to/audio-or-video \
  --output /path/to/transcript.txt \
  --model gpt-app
```

Описание существующей авторизации: [OpenAI, app-server authentication](https://learn.chatgpt.com/docs/app-server#auth-endpoints).

## API

Первые три модели используют официальный endpoint:

```text
POST https://api.openai.com/v1/audio/transcriptions
```

Для diarization отправляются `response_format=diarized_json` и `chunking_strategy=auto`.
Для `gpt-transcribe` также включается `chunking_strategy=auto`, чтобы сервер выбирал границы по паузам внутри каждого локального фрагмента.

Сохранённое аудио или видео можно обработать из командной строки без вывода ключа из Keychain:

```bash
./dist/Transcribator.app/Contents/MacOS/TranscribatorMac \
  --transcribe-existing /path/to/audio-or-video \
  --output /path/to/transcript.txt \
  --model gpt-transcribe
```

Исходная запись не изменяется, временные фрагменты создаются в отдельной папке и удаляются после успеха или ошибки. Чтобы recovery-режим не пересекался с активной записью, перед его запуском закройте menu-bar приложение.
